# OpenCode 単体運用でのコンテキスト管理

対象: #90。調査日: 2026-11-28。想定バージョン: v2.4.2（公開リリース確認済み、利用端末の実効版は未確認）。

## 直ちに試す設定案

OpenCode V2 の [compaction](https://opencode.ai/docs/compaction/) と [config](https://opencode.ai/docs/config/) の現行公式文書を参照した。次は利用者による承認・実効設定確認後の試行値であり、自動適用しない。

```json
{
  "compaction": {
    "auto": true,
    "background": false,
    "keep": { "tokens": 12000 },
    "buffer": "65%"
  },
  "tool_output": {
    "max_lines": 300,
    "max_bytes": 16384
  }
}
```

- buffer は空けておく割合。65%なら入力窓の35%付近が圧縮開始の目安。128Kなら約44.8K、200Kなら約70K、1Mなら約350K。32Kや64Kの絶対制限ではない。小さい窓で保持量・固定指示・出力余裕が収まらない場合は適用せず、モデルごとに見直す。
- keep.tokens は保持する最近の履歴の概算であり、総入力上限ではない。background を無効にする理由は使われない先行要約の消費を避けるため。待ち時間増加やキャッシュ再構築のコストもあり、削減効果は未計測。
- tool_output はツール結果の保持量を抑える。切り詰められたログは必要な範囲を再取得する。すべての入力経路・添付・MCPを網羅するハードリミットとはみなさない。
- V1 の reserved/prune/tail_turns を V2 の設定として混ぜない。既定モデル、価格、モデル限界、権限、Data Policy、APIキー、cache TTL、compaction用モデルはこの案で変更しない。要約もAPI費用が発生し得る。
- 現行公式文書は更新される。v2.4.2 における各キーの受理・実効性は利用端末で確認するまで未検証。未対応キーの黙殺を成功扱いしない。

## 適用・撤回（利用者の端末、API推論なし）

1. 作業中のセッションを終了し、`opencode --version`、`opencode debug config`、`opencode debug paths`、`nepoforge status` を確認する。出力はローカルだけで扱い、認証情報・パス・研究内容を公開しない。CLIは版によって異なるので help を確認する。
2. 設定の由来と衝突を確認する。全プロジェクトに適用するなら既存ユーザー設定の opencode.json(c)、試行プロジェクトだけなら既存の利用者管理プロジェクト設定を選ぶ。Nepoforge生成物、管理者設定、別の権限規則を変更しない。既存の compaction と tool_output を含む対象ファイルをローカルにバックアップし、差分を確認する。秘密を含むバックアップをGitに入れない。
3. 利用者の承認後、上記2項目のキーだけマージする。ファイル全体を上書きしない。モデルや提供経路・予算が適格であることを別途確認する。OpenCode再起動後、設定エラーがなく、選択した版・設定元に対応する項目が反映されることを確認する。実効値を確認できない場合は未確認として扱う。
4. 異常・圧縮ループ・指示消失・ツール出力不足が発生したら停止し、バックアップとの差分から変更したキーだけを戻す（新規作成ファイルならそのファイルのみ撤去）。再起動して元の設定を確認する。他者の後続変更を一括上書きしない。

## 暫定運用

Issue・PR・コミット・研究ノートを作業状態の正本とし、既存 AGENTS.md に従う。原則1 Issue 1セッションだが、複数の密接な変更を機械的に分断しない。検索で読む対象を限定し、巨大な出力はローカルファイルに退避して該当範囲を読む。テストログは終了コード・失敗箇所・必要な前後だけを返す。局所テストとCIを分担し、独立レビューは差分・要求・証拠を入力とする。レビューや引継ぎで会話全文を転載しない。

32K付近は見直し、64K付近は区切りを検討する暫定的なソフト目標。UI表示とプロバイダーの課金単位は異なる。新規セッションの前に現在の目的・制約・決定・変更SHA・検証・残件・次アクションをIssue/PRまたは非公開の作業記録に残す。機密情報を含む記録を公開しない。圧縮の費用が新規セッションの再読込より高いこともあるため、各区切りで選ぶ。必要な安全情報や検証を削ってはならない。

FastMetal等の提供元側で利用者が承認した支出上限を設定・確認する。コンテキスト設定は累積費用、並行実行、内部retry、in-flightの強制制御ではない。予算エラー・異常な反復・設定や料金の不明時は新規送信と自動再試行を停止し、人間判断に戻す。#15/#61/#84/#86の管理下ガードを代替しない。

## 既存データによる比較（追加推論なし）

利用端末で `opencode stats --help` を確認し、対応していれば次をローカルで実行する。

```sh
opencode stats --days 7 --project . --models --cost
opencode stats --days 7 --project . --json
```

既存の [scripts/cost_audit.py](../../scripts/cost_audit.py) の help、対応DBスキーマ、価格基準を確認して再利用する。DBの実際の場所は `opencode debug paths db` 等で特定する。監査は停止済みのOpenCodeの記録を用い、DB・WAL・SHMのコピーに秘密が残らないよう管理し、公開しない。既存スクリプトの価格は推定用でキャッシュ実単価を保証しない。既存の集計で不足する項目は unknown とする。

直接指示と /nfgo の分類は起動記録・Issueとの対応が確実なものだけ。曖昧なセッションは unknown としタイトルだけで断定しない。期間・モデル・タスク・親子・再試行・完了品質を揃えられない比較は参考とする。

記録する値: 完了タスク数、要求充足/CI/レビュー、総入力（非キャッシュ・cache read/writeの定義を確認）、出力・推論、リクエスト数、入力の中央値・上位分位、ツール出力サイズ、圧縮の回数/費用、総費用（請求実額/推定/不明）、時間。単一リクエスト平均だけでは評価しない。提供元の集計対象・時刻境界・課金トークン定義を照合し、重複集計を避ける。改善後の比較は別途承認された通常作業の記録を利用し、検証目的の追加有料実行は行わない。
