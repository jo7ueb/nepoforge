# 設計メモ 0008: 予算ゲートと provider 予算超過の扱い

- 状態: 採用 (#15・#61-b)
- 実装: `nepoforge/budget.py` (純粋関数) / テスト `tests/test_budget.py`
- 関連: #15、#61、#12、設計メモ 0005 (§4.4 規則 1 (c))、`/nfgo` の「タスク計画の管理」

## 1. 背景と実測

#52 の 10 並列試験 (PR #60) で、provider 側の予算超過 (`Budget has been exceeded!`)
により子タスクが 2/10 失敗した。#12 の事後監査 (`scripts/cost_audit.py`) では、
**親セッション自体が予算超過エラー (deepseek ×3・japan-glm-flash ×2) を受けた後も
実行を継続**していたことが判明した。「予算超過後に新規有料起動と自動再試行を
即時停止する」という合意規約が、現行の実行手順では強制されていない。

## 2. 規則 (起動前ゲート)

有料タスクの起動は、次の順で判定してすべて通過した場合のみ許可する
(`nepoforge.budget.decide_launch`)。

1. **停止モード**: provider の予算超過を検知した後は、予算残高にかかわらず
   新規有料起動・自動再試行を拒否する。
2. **上限の設定**: 予算上限 (円) が未設定・不明なら拒否する。
   未設定を無制限と解釈しない。
3. **価格の既知性**: 単価表に登録のないモデルの有料起動は拒否する。
4. **収支判定**: `実績 (spent) + 実行中タスクの予約額 (reserved) + 見積り`
   が上限を超えるなら拒否する。見積りは上限値 (最悪値) で行い、
   自動再試行回数分を積む。

拒否時は理由 (停止モード・未設定・価格不明・予算不足) を必ず報告に含める。

## 3. 予算超過を検知したときの停止手順

`on_budget_error()` が返す指示に従う:

- 新規有料起動・自動再試行を即時停止する。残高が回復しても自動では再開しない。
- 進行中の有料タスクは、安全に停止できる場合のみ停止する。
- 状態と理由を人間に報告する。**再開は人間の明示承認後のみ。**
- 課金なしのローカル検証 (単体テスト・モック・既存ログ解析) は継続してよい。

## 4. 価格データ

- 単価表 (`budget.PRICES`) は円 / 100万 token (入力, 出力・推論を含む・税別)。
- **価格基準日 (2026-11-26 の #61 掲載値) を明記し、請求実額と区別する。**
  cacheRead は入力単価で概算する (実条件は未確認)。
- 単価表の手動更新は、FastMetal の掲載確認とセットで行う。
  価格不明モデルの有料起動は常に拒否されるため、登録漏れは停止として現れる。

## 5. 強制可能な制約と努力目標の区別

| 制約 | 強制 | 補足 |
| --- | --- | --- |
| 起動前の予算判定 | **強制可能** | 純粋関数で判定し、起動コマンドの前に実施する |
| 予算超過後の再起動禁止 | **強制可能** | 停止モードを Coordinator の手順として固定 |
| 見積りに使う上限トークン数 | 強制不可 | provider・OpenCode 側で出力上限を技術的に強制できない。見積りの前提であり、超過時は実績として次回の判定に反映する |
| 支出の正確な計上 | 強制不可 | cost=0 を返す provider を無料とみなさない (#12)。実績は監査ツールと請求の突合で補正する |

## 6. 接続境界

- **CLI 接続 (実装済み)**: `nepoforge plan validate <計画JSON>` が計画を検証し、
  `nepoforge plan ready <計画JSON>` が 計画検証 → Model Resolver (#52) による
  モデル解決 → `planning.ready_tasks` による ready 判定 → `decide_launch` による
  予算ゲート を順に適用し、`launch` / `denied` / `not_ready` / `resolved` を
  返す (課金なし)。`/nfgo` の Coordinator はこの結果に従って委譲する。
- `planning.ready_tasks` (設計メモ 0005・PR #62) が返す起動候補に対し、
  1 タスクごとに `decide_launch` を通してから委譲する。
- 実行履歴の自動記録 (実行ごとの機械可読な記録) は #12 の範囲。
  本実装は実行せず、判定と理由の生成のみを行う。
